# Стек и инфраструктура

## Состав

- **Backend**: Laravel 13, PHP 8.4 — единый монолит, без отдельного bot-сервиса (ТЗ: "не создавать второй независимый backend ради Telegram").
- **БД**: PostgreSQL 16.
- **Очередь/кэш**: Redis 7 (`QUEUE_CONNECTION=redis`).
- **Telegram-слой**: без стороннего SDK — [[TelegramClient]] (собственная тонкая обёртка над Bot API через `Http::post`). Решение осознанное, см. [[Решения#Без Telegram SDK]].
- **Медиа-хранилище**: диск `media` (`config/filesystems.php`) — локальная приватная папка в разработке, S3-совместимое хранилище в РФ (Selectel/VK Cloud и т.п.) в проде через `MEDIA_DISK_DRIVER=s3` + `AWS_*`, без изменений в коде. Подробности — [[Фаза 05 — Медиа]].
- **Окружение**: Docker Compose (`app`, `queue`, `db`, `redis`), локально PHP/Composer не установлены — все artisan-команды идут через `docker compose exec app`.
- **Бэкапы**: диск `backups` (тот же паттерн, что и `media`), ежедневный дамп `db:backup` через планировщик Laravel. `pg_dump`/`pg_restore` в образе `app`/`queue` — пакет `postgresql16-client`, версия зафиксирована под тег `postgres:16-alpine` сервиса `db`, а не generic `postgresql-client` (см. пойманный баг в [[Фаза 07 — Прод-готовность]]).
- **Мониторинг**: Sentry (`sentry/sentry-laravel`, молчит без `SENTRY_LARAVEL_DSN`) + `system:health-check` каждые 15 минут — вебхук/очередь/БД, алерт владельцу в Telegram при проблеме.

## Почему не Laravel Sail / Boost

Проект генерировался стандартным Laravel-инсталлятором, который принёс `CLAUDE.md`/`AGENTS.md` с инструкцией поставить PHP локально и `laravel/boost`. Решили не ставить — Docker уже даёт рабочее окружение, а Boost на момент разработки не давал новых инструментов внутри уже идущей сессии. См. [[Решения#Docker вместо локального PHP]].

## Известный готча: Cyrillic-путь + BuildKit

Путь проекта содержит кириллицу и пробел (`...\Рабочий стол\Новая папка`). Buildx/BuildKit падает на этом с `rpc error: ... non-printable ASCII characters`. Сборки идут с `DOCKER_BUILDKIT=0` (legacy builder) и `MSYS_NO_PATHCONV=1` (иначе Git Bash на Windows коверкает пути в `docker run -v`). Имя compose-проекта задаётся явно (`-p service_ops`), иначе `docker compose` не может вывести имя из кириллического пути папки.

## Переменные окружения

Помимо стандартных Laravel — блок `TELEGRAM_*` (токен, webhook secret, owner id) и `INTERNAL_API_KEY` (защита `/api/v1/*`). Список и назначение — в `.env.example` в репозитории, дублировать здесь не нужно (см. правило "не документировать то, что видно из кода за 5 секунд").

## Тестовое окружение

`phpunit.xml` форсирует свои `env` через `force="true"` поверх контейнерных. Без этого `docker-compose`-совместимые переменные из реального `.env`, попадая в `$_SERVER` при старте PHP-процесса, не давали PHPUnit их переопределить — тесты тихо гоняли `RefreshDatabase` по dev-базе в Postgres вместо sqlite `:memory:`. Подробности — [[Решения#PHPUnit env vs $_SERVER]].
